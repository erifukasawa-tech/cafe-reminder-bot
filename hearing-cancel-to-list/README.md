# ヒアリングキャンセル → キャンセルリスト 自動転記（GAS）

TimeRex で予定がキャンセルされると、`#2-ヒアリング予約通知__今は売買のみ` に TimeRex ボットが
「〇〇さんが予定をキャンセルしました。」と投稿します。
この Google Apps Script は5分おきにその通知を確認し、次の3つを自動で行います。

1. **案件管理シート**の `売買管理` タブから、該当する案件を探す
   - 照合の順番：① TimeRex のイベントID（`イベントID` 列）→ ② 氏名＋ヒアリング日 → ③ 氏名だけ
2. **キャンセルリスト**の `キャンセル追客リスト` タブの一番上（2行目）に1行追加する
3. 通知のスレッドに「キャンセルリストに追加しました」と返信する

## 自動で入る列 / 人が入れる列

| 列 | 中身 |
|---|---|
| 案件番号・担当・反響日・LstepURL | 売買管理の `#`・`担当`・`反響日`・`URL` |
| 流入経路 | 売買管理の `備考` に入っている「流入:〇〇」（ない場合は `獲得方法`） |
| 当初ヒアリング日 | TimeRex 通知に書かれた予定日 |
| お客様名 | 売買管理の `顧客名`（見つからなければ TimeRex の名前） |
| キャンセル連絡日 | 通知が届いた日 |
| TimeRexURL | `https://timerex.net/user/event/<イベントID>` |
| 状況・お客様情報 | `【自動追加 M/D】…` のメモ |
| アポ取得・追客ストップ | FALSE |
| **キャンセル理由・リスケURL送付日・追客メモ** | **これまでどおり担当が記入** |

- すでに同じお客様（TimeRexURL が同じ、または案件番号か氏名と当初ヒアリング日が同じ）の行があるときは追加しません。スレッドには「すでに〇行目にあります」と返信します。
- 案件が見つからなかったときも行は追加します。その場合、案件番号などは空欄になり、スレッドに :warning: が付きます。

## セットアップ（最初の1回だけ）

### 1. Slack アプリ（ボット）を用意する

1. https://api.slack.com/apps で「Create New App」→「From scratch」を選ぶ（名前の例：`キャンセルリスト転記`）
2. 「OAuth & Permissions」→「Bot Token Scopes」に次を追加する
   - `channels:history`（チャンネルが非公開なら `groups:history` も）
   - `chat:write`
3. 「Install to Workspace」でインストールし、**Bot User OAuth Token**（`xoxb-` で始まる文字列）を控える
4. Slack の `#2-ヒアリング予約通知__今は売買のみ` で `/invite @キャンセルリスト転記` を実行し、ボットをチャンネルに招待する

### 2. GAS プロジェクトを作る

1. https://script.google.com で「新しいプロジェクト」を作る（名前の例：`ヒアリングキャンセル転記`）
   - 案件管理シートとキャンセルリストの**両方を編集できるアカウント**で作ってください
2. `Code.gs` の中身を、このフォルダの [Code.gs](Code.gs) で置き換える
3. 「プロジェクトの設定」→「`appsscript.json` マニフェスト ファイルをエディタで表示する」をオンにし、[appsscript.json](appsscript.json) の中身を貼り付ける
4. 「プロジェクトの設定」→「スクリプト プロパティ」に次を追加する
   - プロパティ：`SLACK_BOT_TOKEN`　値：手順1で控えた `xoxb-...`

### 3. 試し実行 → 本番開始

1. エディタで関数 `dryRun` を選んで実行する（初回は権限の許可を求められます）
   - 直近7日のキャンセル通知について「何を書き込むか」がログに出るだけで、シートや Slack は変わりません
   - ログの `eventId` が空の場合、TimeRex 通知にイベントURLが入っていないので、氏名＋ヒアリング日で照合されます
2. 内容に問題がなければ、関数 `setup` を実行する → 5分おきの自動実行が始まります（それより前の通知は対象外）
3. 過去1週間ぶんも取り込みたいときは、`backfill` を1回実行する（すでにリストにある人は自動でスキップされます）

## 注意

- **担当変更などで社内の人が TimeRex の予定を消した場合**も、同じキャンセル通知が出ると、リストに追加されます。そういう行は削除してください。
- すでに動いている「ヒアリング日を過ぎてもヒアリングシートがない人を【自動追加・要確認】で入れる仕組み」は、別のシステムです。そちらの重複チェックがこの仕組みの行も見ているかは、作った人に確認してください。
- 売買管理の列名（`#`・`顧客名`・`イベントID` など）や、キャンセルリストの見出し名を変えると、照合や転記がずれます。列の**位置**は変わっても大丈夫です（見出し名で探しています）。
- エラーで止まったときは、GAS の「実行数」画面にエラーが出て、トリガーの失敗通知メールがプロジェクトのオーナーに届きます。
