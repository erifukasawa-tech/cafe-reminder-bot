# 売買ヒアリングに社長を自動招待するRoutine

`info@naikenboys.co.jp` カレンダー上の今後の売買ヒアリング予定を確認し、社長(中島さん `sho_nakajima@naikenboys.co.jp`)が参加者に入っていないものに追加します。

Routine: https://claude.ai/code/routines/trig_019LU3P4ZdZWHrq5UU7ouZmd
(claude.ai の画面から作成したRoutineのため、Claude側からは編集できません。設定変更は画面から行ってください。)

## 設定

- スケジュール: 毎日 8:07〜20:07 (Asia/Tokyo) の1時間ごと
  - cron: `CRON_TZ=Asia/Tokyo 7 8-20 * * *`
- コネクタ: Google Calendar(他は不要)
- プロンプト: 下記をそのまま貼り付け

## 2026-10-30 の見直し内容

10月に社長が入っていない売買ヒアリングが10件あった。

- 8件(西川・坂口・柴辻・津野・金本・安本・宇原・田頭)は数日前に登録されていたが、開始の0〜1時間前に担当営業側で予定が更新されており、その時点で社長が参加者に入っていなかった。朝1回の実行では、当日の更新で外れたあとに追加し直す機会がなかった。
- 2件(永岡・阿部)は当日、朝の実行後に登録された。
- 担当営業が意図的に社長を外す運用はないため、外れていたら追加し直す方針にした(深澤さん確認済み)。

変更点:

1. 朝1回 → 8時〜20時の毎時実行にして、当日登録・当日の更新で外れたケースを拾う。
2. 取得を14日ずつに分けてページ送りを徹底し、取りこぼしを防ぐ。取得期間は90日 → 60日。
3. 追加後に get_event で反映を確認する。
4. 判定語に renewal_OSAKA / 査定 を追加し、定例・面接を除外語に追加。
5. 追加も失敗もない回は通知しない(毎時実行で通知が多くなりすぎないように)。

## プロンプト

```
あなたは株式会社ないけんぼーいずのバックオフィス(深澤)の代理で、売買ヒアリングの予定に社長を招待する作業を行います。この作業は毎日8:07〜20:07(JST)に1時間ごとに自動実行されます。ユーザーへの確認は不要です。自律的に最後まで実行してください。

## 手順
1. 現在時刻をJST(UTC+9)で把握する。
2. Google Calendar コネクタで、カレンダー info@naikenboys.co.jp の予定を「現在時刻〜60日後」まで取得する。1回の list_events で取りこぼさないよう、期間を14日ずつに区切って list_events(calendarId=info@naikenboys.co.jp, orderBy=startTime, pageSize=250)を呼び、nextPageToken があれば必ず全ページ取得する。結果が大きくファイルに保存された場合は jq で処理し、件数(events|length)と nextPageToken の有無を必ず確認する。
3. 次のいずれかに当てはまる予定を「売買ヒアリング」とみなす:
   - タイトルに renewal_BUY / BUY_ / : BUY / SELL / renewal_OSAKA / 売買 / 売却 / 購入 / 査定 を含む(大文字小文字無視。SHIBUYA など単語の一部の BUY は除外)
   - タイトルに ヒアリング(再ヒアリング・オンラインヒアリング含む)を含む
   除外: タイトルに RENT / 賃貸 / 勉強会 / 定例 / 社長カフェ / ばっちカフェ / 面接 を含むもの、キャンセル済みの予定、開始時刻が既に過ぎた予定。
4. 対象のうち参加者に sho_nakajima@naikenboys.co.jp が含まれていない予定は、すべて update_event(calendarId=info@naikenboys.co.jp, eventId, addedAttendees=[{"email":"sho_nakajima@naikenboys.co.jp"}])で社長を追加する。以前追加したのに後から外れている予定も、同じように必ず追加し直す(社長を意図的に外す運用はないため)。他の参加者・説明文・時刻などは一切変更しない。社長が辞退(declined)済みの予定には再追加しない。
5. 追加した予定はそれぞれ get_event で取得し直し、参加者に sho_nakajima@naikenboys.co.jp が入ったことを確認する。入っていなければもう一度 update_event を行い、それでも入らなければ失敗として報告する。
6. 最後に、追加した予定(日時・タイトル・eventId・更新日時 updated)、失敗した予定、判定に迷ってスキップした予定を一覧で報告する。追加・失敗がどちらも0件なら「追加なし」とだけ出力し、通知(PushNotification)は送らない。追加または失敗が1件以上あるときだけ通知を送る。
```
