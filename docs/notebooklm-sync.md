# バックオフィス周知 → NotebookLM 自動転記

Slack `#1-全体-バックオフィス周知` (channel_id: `C06A4MB1QB0`) の投稿を、平日毎朝 Routine が Google ドキュメントに追記します。NotebookLM ではこのドキュメントをソースとして登録しておくだけで、毎回の手動アップロードが要らなくなります。

- 転記先ドキュメント: [LM用資料](https://docs.google.com/document/d/1SO5uhb0YqGVNnlho1hL1sEMLee-fmstC6tttO2PbSAo/edit)
  - documentId: `1SO5uhb0YqGVNnlho1hL1sEMLee-fmstC6tttO2PbSAo`
- 転記内容: **社内ルール・制度・運用方法の通知文だけ**を、ほぼ原文のまま（日時・投稿者付き）。投稿者本人がスレッドに書いた補足・訂正も一緒に入れる。時間割・落とし物・アンケート・提出依頼・勤怠や有給の状況などの一時的な連絡は入れない。
- 重複防止: 各投稿の末尾に `[slack_ts:...]` を書き、次回はそれより新しい投稿だけを取り込む。数日 Routine が止まっても、次の実行で抜けた分をまとめて取り込む。

## 初回セットアップ

1. **NotebookLM にソース追加**: ノートブックで「ソースを追加」→「Google ドライブ」→ 上記ドキュメントを選ぶ（1回だけ）。
2. **Routine を作成**（カフェリマインドと同じく claude.ai の Routines 画面から手動で作成）:
   - 名前: `平日朝 バックオフィス周知→NotebookLM転記`
   - スケジュール: 平日 8:50 (JST)
   - 実行方式: 毎回新しいセッションで実行
   - **コネクタ: Slack と Google Drive（Google Docs）を ON**
   - プロンプト: 下の「Routineプロンプト」をそのまま貼り付け
3. 保存後、一度「今すぐ実行」して、ドキュメントに過去30日分が入ることを確認する。

## 運用メモ

- NotebookLM 側の Google ドライブソースは自動で最新化されない場合があります。その場合は、NotebookLM でソースを開いて「Google ドライブと同期」を押すと最新の内容が反映されます。
- ドキュメントが大きくなりすぎた場合（目安: 数十万字）は、ドキュメントを年度ごとに分けて、新しいドキュメントの documentId に下のプロンプトを書き換えてください。
- 入れる／入れないの基準を変えたい場合は、プロンプトの手順4を書き換えて、claude.ai の Routine のプロンプトも同じ内容に更新してください。

## 手順

1. Google Docs の read_doc で転記先ドキュメントを読み、本文中の `[slack_ts:数字.数字]` をすべて探して、最大の値を「前回の取り込み位置」とする。1つも無ければ(初回)、現在時刻から30日前のUnix時刻を取り込み位置とする。

2. slack_read_channel(channel_id: C06A4MB1QB0, oldest: 取り込み位置)で、それより新しいトップレベル投稿を全件取得する(next_cursor があれば最後までページングする)。取り込み位置とtsが完全に一致する投稿は取り込み済みなので除外する。

3. 各投稿について、スレッド返信がある場合は slack_read_thread で読み、**元の投稿者本人による返信**(補足・訂正・期限変更など)だけを拾う。他の人の質問やお礼などの返信は入れない。

4. 転記するかどうかを1投稿ずつ判定する。**社内のルール・制度・運用方法を伝える通知文だけ**を転記し、それ以外はすべて転記しない(迷ったら転記しない)。

   転記する(=後から「ルールはどうなっていたか」を調べるときに必要になる投稿):
   - 就業規則・勤怠・休暇・振替休日・休日出勤などのルールや申請方法の新設・変更
   - 経費・発注・決裁・契約承認などの社内手続きのルールや権限の新設・変更
   - マニュアル・規程の更新のお知らせ(何が変わったかの説明とリンク)
   - オフィスの利用規則・遵守事項・セキュリティのルール、引越しなど今後の運用に関わる決定事項
   - 社長カフェ等の定例制度の仕組み・ルール(奇数月/偶数月の割り当て、予約方法など)

   転記しない:
   - その日限り・その回限りの連絡(研修やコンサルの時間割、会議URL、当日の勤務連絡など)
   - 落とし物・探し物の呼びかけ、イベントの報告・お礼・雑談
   - アンケート回答、書類・SUICA履歴などの提出依頼、給料明細格納のお知らせ、eラーニング受講のお願い
   - 毎月の締切リマインド(「〇月分の経費申請・勤怠チェックは〇日まで」など、ルール自体の変更を含まないもの)
   - 勤怠・有給取得状況・進捗などの状況報告や集計(スナップショット等)
   - 建物の点検・工事などのお知らせ
   - Slackのシステムメッセージ、本文が空の投稿

   1つの投稿にルールの通知と一時的な連絡が混ざっている場合は、投稿全体を原文のまま転記してよい。

5. 古い順に並べ、1投稿ごとに以下の形式のテキストを作る。

========================================
■ {YYYY-MM-DD(曜) HH:MM} / 投稿者: {表示名}
{本文}
{(スレッド補足がある場合)
【スレッド補足 {MM-DD HH:MM}】
{補足本文}}
[slack_ts:{投稿のts}]

本文の整形ルール(内容は要約・言い換えせず、原文のまま残す):
- 日時はJST(UTC+9)で書く。
- `<!subteam^...>` や `<!channel>` などのグループメンションは削除する。`<@Uxxxx|名前>` は「@名前」にする。
- `<https://...|表示テキスト>` 形式のリンクは「表示テキスト (https://...)」にする。リンクのURLは省略しない。
- Slackの装飾記号(*太字*、`コード`、_斜体_、> 引用 の記号)は外してプレーンテキストにする。絵文字コード(:fire: など)は削除する。
- 末尾の「使用して送信されました @Claude」のような送信元表記は削除する。
- 添付ファイルがある場合は「(添付: ファイル名)」と1行書く。

6. 新しい投稿が1件も無ければ、ドキュメントは変更せずに終了する。

7. 新しい投稿があれば、Google Docs の update_doc で insertText(endOfSegmentLocation: {})を使い、作ったテキストをまとめてドキュメント末尾に追記する(先頭に改行を1つ入れる)。既存の内容は絶対に書き換え・削除しない。

8. 追記が完了したら終了。Slackへの投稿や報告は不要。エラーで転記できなかった場合だけ、深澤さん(Slack user id: U08NUG11WBG)にDMで「バックオフィス周知の自動転記に失敗しました: {理由}」と送る。
